# Устройство проекта

Проект использует обычные HTML, CSS и JavaScript без модулей и фреймворков.
Порядок `<script>` в `index.html` важен: файлы используют общие переменные
и расширяют функции, объявленные ранее.

| Файл | Содержимое |
| --- | --- |
| `assets/boot.js` | Начальные сообщения загрузки и обработка ошибки запуска |
| `assets/vendor/three.r128.min.js` | Three.js r128 UMD |
| `assets/vendor/GLTFLoader.r128.js` | GLTFLoader для той же версии Three.js |
| `assets/catalog-data.js` | CATS, PARTS и INTERNAL с описаниями деталей |
| `assets/technical-data.js` | Учебный профиль, технические уточнения и источники |
| `assets/viewer-core.js` | Базовая сцена, камера, каталог, панель детали и прогресс |
| `assets/vendor/fflate.umd.js` | Распаковка gzip |
| `assets/model-loader.js` | Загрузка и разбор GLB, материалы и элементы импортированной модели |
| `assets/unified-vehicle.js` | Объединение модели с учебными механизмами и анимацией |
| `assets/interface.js` | Панели, фокус, управление и подписи интерфейса |
| `assets/course-data.js` | Задания, ситуации, разборка, потоки и сцены защиты |
| `assets/course.js` | Выполнение занятий, результаты, движение потоков |
| `assets/lab.js` | Главная, маршрут, системы, закладки и управление тактами |
| `assets/layout.js` | Раздельные области модели и текста, сворачивание панелей |
| `assets/readable.js` | Настройки чтения, помощь, крупный текст и синтез речи |

Стили подключены в порядке `interface.css`, `lab.css`, `layout.css`,
`readable.css`. Последние файлы уточняют компоновку и читаемость.

## Модель

`assets/cobalt-mobile.glb.gz` содержит сжатый GLB. Приложение получает его
обычным `fetch`, распаковывает fflate и передаёт в GLTFLoader.
Модель использует `KHR_mesh_quantization`; Draco-декодер не нужен.

После загрузки `window.installUnifiedVehicle` создаёт учебные механизмы
и связывает меши с идентификаторами каталога. Внешние оболочки и внутренние
детали участвуют в одной сцене и одном выборе через raycaster.

## Добавление деталей

1. Добавь описание в `PARTS` или `INTERNAL`.
2. Реализуй геометрию и её соответствие `id` в `unified-vehicle.js`.
3. При необходимости добавь связи и задания.
4. Сохрани существующие `id`: по ним работают прогресс и закладки.
5. Запусти проверки и пересобери `cobalt.html`.

Число узлов в готовой версии — 94. При расширении каталога обновляй
соответствующие числовые подписи главной и описание проекта.

## Данные браузера

| Ключ localStorage | Назначение |
| --- | --- |
| `cobalt_studied_v1` | Изученные детали |
| `cobalt_courses_v1` | История завершённых занятий |
| `cobalt_bookmarks_v1` | Сохранённые детали |
| `cobalt_home_seen_v1` | Первый вход на главную |
| `cobalt_readability_v1` | Размер текста и тема |

Не меняй формат существующих ключей без обработки старых значений.
Приложение не синхронизирует данные между разными адресами сайтов.

## Проверки

`check-project.py` и `check-js.cjs` проверяют переносимость и целостность файлов.
`check-model.cjs` использует настоящие Three.js и GLTFLoader с заменой DOM
и WebGLRenderer на заглушки. Это проверка геометрии и связности каталога,
а не снимок экрана или замер производительности телефона.
