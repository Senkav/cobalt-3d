# Публикация на GitHub Pages

## Содержимое репозитория

В корне должны находиться `index.html`, `cobalt.html`, `assets`, `scripts`
и `.github/workflows/pages.yml`. Загрузи и `licenses` с уведомлениями об авторах.
Переносить файлы внутрь дополнительной папки или переименовывать `assets`
не нужно. Пути рассчитаны и на адрес проекта с подпапкой репозитория.

## Настройка

1. Основная ветка: `main`.
2. **Settings → Pages → Source → GitHub Actions**.
3. Разреши выполнение GitHub Actions в настройках репозитория, если оно отключено.
4. Запусти `Check and publish Cobalt 3D` во вкладке **Actions**.

Workflow сначала проверяет файлы, JavaScript, геометрию и одиночный HTML.
Затем копирует публичные файлы в `_site` и публикует их.
Документация разработки и служебные проверки в опубликованный сайт не попадают.
Проверки pull request выполняются без публикации.

Дополнительные ключи API, токены в исходниках и серверная база не нужны.
Стандартное разрешение публикации выдаёт GitHub Actions.

## При изменениях

После изменения исходников выполни:

```bash
python3 scripts/build-standalone.py
```

Сохрани исходники и `cobalt.html` одним коммитом в `main`.
Публикация запускается автоматически.

## Если публикация не прошла

- `cobalt.html is stale`: пересобери одиночный HTML указанной командой.
- Отсутствует файл из `assets`: загрузи папку целиком и сохрани имена файлов.
- Ошибка настройки Pages: проверь источник GitHub Actions, затем повтори запуск.
- Задание ожидает разрешения окружения: открой запуск Actions и проверь
  правила окружения `github-pages` в настройках своего репозитория.

## Если модель не загрузилась

- Открывай сайт по ссылке Pages, а не `index.html` через файловый просмотрщик.
- Для запуска без сервера используй `cobalt.html`.
- Убедись, что `assets/cobalt-mobile.glb.gz` загружен полностью.
- Браузер должен поддерживать WebGL и JavaScript.

На другом статическом хостинге не назначай заголовок `Content-Encoding: gzip`
самому файлу `cobalt-mobile.glb.gz`: приложение распаковывает его самостоятельно.

Официальная инструкция:
[GitHub Pages custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
